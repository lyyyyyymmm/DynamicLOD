# 1 引言

Web 端三维可视化正在承载摄影测量模型、城市建筑、工程构件和文化遗产等规模不断扩大的空间数据。此类数据往往同时包含高密度几何与多层纹理，完整载入和全分辨率绘制会迅速触及终端的显存、网络带宽和单帧计算能力。层次细节（Level of Detail，LOD）因而不是单纯的显示选项，而是浏览器维持连续交互的基础机制。3D Tiles 1.1 以层次包围体、几何误差和屏幕空间误差（Screen-Space Error，SSE）描述瓦片细化条件，使客户端能够依据观察距离、视锥关系和显示分辨率判断当前可见瓦片是否需要继续细化 [@OGC3DTiles2022]。这一机制有效回答了“当前视角需要多细”的问题，但固定的最大 SSE 本质上仍是预先给定的质量偏好，不能直接表达“P95 帧时不超过既定预算”这样的运行时约束。

在复杂场景中，平均帧率并不足以刻画用户实际感知到的卡顿。相机运动会同时改变可见集合和细化需求，瓦片下载、解码与上传又以异步方式进入浏览器和渲染管线；JavaScript 执行、资源处理及 GPU 同步造成的短时阻塞，常被均值平滑，却会集中反映在帧时分布的尾部。与此同时，当前帧时只描述已经发生的负载，无法单独揭示正在积累的请求与处理压力。若控制器仅在某一帧变慢后提高 SSE，调节可能晚于负载上升；若在帧时短暂回落后立即恢复细节，则容易在质量等级之间反复切换。Web 3D Tiles 的运行时质量调度因此需要同时面对性能约束的尾部特征、流式请求的滞后效应以及交互阶段对卡顿和清晰度恢复的不同容忍度。

以目标帧时为边界进行自适应显示并非新的问题。Funkhouser 和 Sequin 将交互式绘制表述为帧时预算内的显示质量选择，为“在资源约束下调节细节”建立了经典思路 [@Funkhouser1993]。后续研究也表明，运行时预测与质量估计可以用于在资源预算下选择绘制配置，并可覆盖桌面与移动平台 [@Zhang2018]。然而，Web 端层次瓦片具有自身的控制条件：质量执行器由既有 SSE 细化流程提供，负载不仅来自可见几何，还来自网络请求和瓦片处理队列；交互期间的降质响应与停止交互后的质量恢复也不宜采用对称规则。现有材料分别提供了预算约束、自适应预测和多分辨率传输的依据，但不能直接给出一个只依赖公开 Cesium 遥测信号、面向尾部帧时并显式抑制振荡的 3D Tiles 调度方案。

基于这一问题边界，本文研究能否通过轻量且可解释的控制器，把近期 P95 帧时、短期变化趋势、公开请求反馈和交互状态转化为最大 SSE 的稳定离散决策。控制器以 Cesium 的 `maximumScreenSpaceError` 为执行量，几何误差投影、可见性判断和瓦片细化仍由 Cesium 与 3D Tiles 标准流程负责。方法对滚动 P95 帧时进行平滑，并利用正向趋势形成一秒期预测；请求队列和瓦片处理状态用于识别尚未完全反映到帧时中的流式压力；交互状态则用于阻止不合时宜的质量升级，同时保留预算超限时的紧急降级通道。滞回条件、连续满足计数和不对称冷却时间共同约束切换频率。这样的定位并不改变网格表示或瓦片编码，而是在既有细化机制外增加一层客户端运行时调度。

本文围绕上述研究问题开展三方面工作：

1. 构建面向尾部帧时约束的 Web 3D Tiles 控制框架，以滚动 P95 帧时为主要受控指标，并用平滑后的短期正向趋势形成一秒期负载预判，使质量决策能够在已观测超限和潜在上升压力之间保持明确对应关系。
2. 设计结合公开请求压力与交互状态的非对称决策规则：交互期间限制质量升级，在帧时预算受到威胁时允许分级降质；质量恢复则要求帧时、预测值和请求状态持续稳定，并通过滞回与冷却机制控制往返切换。
3. 建立可复现的配对评价方案，在固定绘制分辨率和确定性相机路径下，使用公开 Cesium 遥测记录帧时、请求与可见瓦片信息，并设置固定 SSE、Cesium 动态 SSE、反应式 P95 控制器及组件消融作为对照，在 PC 与 Android 设备上检验约束满足、质量代价和调度稳定性。该方案描述的是待执行的验证路径，不预设任何性能优势。

# 2 相关工作

## 2.1 离线模型简化与多分辨率 Web 传输

运行时 LOD 调度以预先构建的多分辨率表示为基础，但模型如何简化与客户端何时选择某一级表示属于两个不同层面。Garland 和 Heckbert 提出的二次误差度量以局部几何代价驱动边收缩，为高效生成简化网格提供了经典方法 [@Garland1997]。这类方法决定离线阶段可供选择的几何层级及其误差特征，却不负责根据浏览器当前负载调整层级选择。本文受控模型的离散 LOD 可沿用既有简化流程，研究对象则限定为这些层级进入 3D Tiles 后的运行时选择，不把离线网格处理视为调度方法的创新来源。

多分辨率数据进入 Web 环境后，LOD 选择还受到设备能力、相机路径、内存占用和绘制负载的共同影响。Suarez 等围绕移动设备上的地形 LOD 实现开展性能研究，说明 iOS、Android 与浏览器环境中的硬件和运行条件会改变多分辨率绘制行为 [@Suarez2015]。Auer 等将语义分割的多分辨率三维模型用于文化遗产的 Web 可视化与查询，表明层次组织能够支持细节丰富模型的在线访问 [@Auer2014]。这些工作从移动性能和应用场景两侧说明了多分辨率传输的必要性，但其论证重点不在利用实时瓦片请求压力约束帧时分布尾部。3D Tiles 标准提供的几何误差与 SSE 则构成通用的层次细化接口 [@OGC3DTiles2022]；本文沿用该接口作为质量执行器，不提出新的瓦片格式、误差编码或内容组织方式。

## 2.2 预算约束下的运行时质量调节

自适应绘制关注的是在资源有限且负载变化的条件下，如何选择当下可承担的表示质量。Funkhouser 和 Sequin 的方法以用户给定的目标帧时约束显示选择，核心思想是将交互稳定性纳入质量优化，而不是始终追求最高精度 [@Funkhouser1993]。这一框架为本文采用明确帧时预算提供了理论起点，但其场景早于 Web 流式瓦片体系，并未包含网络请求与异步处理队列。若直接把经典帧时反馈移植到 3D Tiles，控制器仍可能在请求压力尚未转化为可见卡顿时缺少提前量。

运行时预测为提前调节质量提供了另一条路径。Zhang 等通过在线预测与质量估计，在功耗预算下选择绘制配置，并在桌面和移动平台讨论其适用性 [@Zhang2018]。该研究说明轻量预测可以服务于资源约束下的质量决策，也提示跨设备验证不能由单一硬件结果替代。其优化对象是功耗而非浏览器尾部帧时，输入中也没有 3D Tiles 的请求和处理状态。本文借鉴预算驱动和短期预测的基本思想，把受控量改为滚动 P95 帧时，并将公开请求反馈与交互阶段纳入决策条件；这种继承关系限定了本文的方法来源，也避免把一般性的预测式质量调节表述为新概念。

## 2.3 本文工作的定位

上述研究可以归纳为三条相互衔接但职责不同的技术路线：离线简化负责生成可替换的几何表示，多分辨率 Web 传输负责组织并按视点加载内容，运行时质量调节负责在动态资源边界下选择当前配置。本文位于第三条路线，并依赖前两条路线提供的数据层次与标准化执行接口。其具体问题不是证明更高精度的简化算法，也不是改变 3D Tiles 的层次结构，而是考察在现有 SSE 执行器之上，尾部帧时趋势、异步请求压力和交互状态能否共同形成稳定、可解释的调度信号。

因此，本文的创新边界应理解为一种受约束的调度组合及其验证设计：以 P95 帧时预算界定性能目标，以短时正趋势提供预警，以公开瓦片请求状态补充流式负载信息，再用交互非对称性、滞回和冷却条件限制质量振荡。现有文献矩阵能够支撑这些组成部分的来源、应用动机与差异边界，但不能据此扩大创新范围或预先断言该组合优于既有方法。方法是否降低预算超限、其视觉质量代价是否可接受、稳定控制是否减少反复切换，均须由既定的配对实验和消融分析回答。
