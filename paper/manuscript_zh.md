# 面向尾部帧时约束的 Web 3D Tiles 预测式动态 LOD 调度方法

## 摘要

Web 三维应用需要在视觉细节、帧时稳定性与异步瓦片加载之间持续权衡，而固定屏幕空间误差阈值难以响应相机交互、资源处理和请求突发造成的短时负载变化。本文提出一种面向 Web 3D Tiles 的轻量预测式动态 LOD 调度方法，以两秒滚动窗口的 P95 帧时为约束指标，通过一秒期正趋势预测、Cesium 公开瓦片请求反馈、交互感知的非对称决策以及滞回和冷却机制，在线调节 `maximumScreenSpaceError`。实验方案设置固定 SSE 8、固定 SSE 16、Cesium 动态 SSE、反应式 P95 与离散 PI 控制器作为基线，在两个公开 3DBAG 城市子集、固定绘制分辨率与确定性相机路径下，计划于两台桌面 PC 和一部物理 Android 设备上开展配对重复与组件消融，并以预算超限率、时间加权 SSE、SSIM、补充 LPIPS、切换频率和恢复时间评价性能、质量及稳定性。[待正式实验回填：仅在完整物理设备矩阵、配对统计和视觉质量标定完成后填写主要效果、校正后 p 值、效应量、置信区间及非劣结论。]本文的贡献限定为既有 3D Tiles SSE 细化流程之外的客户端运行时调度，不涉及新的网格简化方法或瓦片编码格式。

关键词：Web 三维；3D Tiles；层次细节；尾部帧时；运行时自适应；WebGIS


# 1 引言

Web 端三维可视化正在承载摄影测量模型、城市建筑、工程构件和文化遗产等规模不断扩大的空间数据。此类数据往往同时包含高密度几何与多层纹理，完整载入和全分辨率绘制会迅速触及终端的显存、网络带宽和单帧计算能力。层次细节（Level of Detail，LOD）因而不是单纯的显示选项，而是浏览器维持连续交互的基础机制。3D Tiles 1.1 以层次包围体、几何误差和屏幕空间误差（Screen-Space Error，SSE）描述瓦片细化条件，使客户端能够依据观察距离、视锥关系和显示分辨率判断当前可见瓦片是否需要继续细化 [@OGC3DTiles2022]。这一机制有效回答了“当前视角需要多细”的问题，但固定的最大 SSE 本质上仍是预先给定的质量偏好，不能直接表达“P95 帧时不超过既定预算”这样的运行时约束。

在复杂场景中，平均帧率并不足以刻画用户实际感知到的卡顿。相机运动会同时改变可见集合和细化需求，瓦片下载、解码与上传又以异步方式进入浏览器和渲染管线；JavaScript 执行、资源处理及 GPU 同步造成的短时阻塞，常被均值平滑，却会集中反映在帧时分布的尾部。与此同时，当前帧时只描述已经发生的负载，无法单独揭示正在积累的请求与处理压力。若控制器仅在某一帧变慢后提高 SSE，调节可能晚于负载上升；若在帧时短暂回落后立即恢复细节，则容易在质量等级之间反复切换。Web 3D Tiles 的运行时质量调度因此需要同时面对性能约束的尾部特征、流式请求的滞后效应以及交互阶段对卡顿和清晰度恢复的不同容忍度。

以目标帧时为边界进行自适应显示并非新的问题。Funkhouser 和 Sequin 将交互式绘制表述为帧时预算内的显示质量选择，为“在资源约束下调节细节”建立了经典思路 [@Funkhouser1993]。后续研究也表明，运行时预测与质量估计可以用于在资源预算下选择绘制配置，并可覆盖桌面与移动平台 [@Zhang2018]。然而，Web 端层次瓦片具有自身的控制条件：质量执行器由既有 SSE 细化流程提供，负载不仅来自可见几何，还来自网络请求和瓦片处理队列；交互期间的降质响应与停止交互后的质量恢复也不宜采用对称规则。现有材料分别提供了预算约束、自适应预测和多分辨率传输的依据，但不能直接给出一个只依赖公开 Cesium 遥测信号、面向尾部帧时并显式抑制振荡的 3D Tiles 调度方案。

基于这一问题边界，本文研究能否通过轻量且可解释的控制器，把近期 P95 帧时、短期变化趋势、公开请求反馈和交互状态转化为最大 SSE 的稳定离散决策。控制器以 Cesium 的 `maximumScreenSpaceError` 为执行量，几何误差投影、可见性判断和瓦片细化仍由 Cesium 与 3D Tiles 标准流程负责。方法对滚动 P95 帧时进行平滑，并利用正向趋势形成一秒期预测；请求队列和瓦片处理状态用于识别尚未完全反映到帧时中的流式压力；交互状态则用于阻止不合时宜的质量升级，同时保留预算超限时的紧急降级通道。滞回条件、连续满足计数和不对称冷却时间共同约束切换频率。这样的定位并不改变网格表示或瓦片编码，而是在既有细化机制外增加一层客户端运行时调度。

本文围绕上述研究问题开展三方面工作：

1. 构建面向尾部帧时约束的 Web 3D Tiles 控制框架，以滚动 P95 帧时为主要受控指标，并用平滑后的短期正向趋势形成一秒期负载预判，使质量决策能够在已观测超限和潜在上升压力之间保持明确对应关系。
2. 设计结合公开请求压力与交互状态的非对称决策规则：交互期间限制质量升级，在帧时预算受到威胁时允许分级降质；质量恢复则要求帧时、预测值和请求状态持续稳定，并通过滞回与冷却机制控制往返切换。
3. 建立基于两个冻结 3DBAG 真实城市子集的可复现配对评价方案，在固定绘制分辨率和确定性相机路径下，使用公开 Cesium 遥测记录帧时、请求与可见瓦片信息，并设置固定 SSE、Cesium 动态 SSE、反应式 P95、离散 PI 及组件消融作为对照，在物理 PC 与 Android 设备上检验约束满足、质量代价和调度稳定性。该方案描述的是待执行的验证路径，不预设任何性能优势。

# 2 相关工作

## 2.1 离线模型简化与多分辨率 Web 传输

运行时 LOD 调度以预先构建的多分辨率表示为基础，但模型如何简化与客户端何时选择某一级表示属于两个不同层面。Garland 和 Heckbert 提出的二次误差度量以局部几何代价驱动边收缩，为高效生成简化网格提供了经典方法 [@Garland1997]。这类方法决定离线阶段可供选择的几何层级及其误差特征，却不负责根据浏览器当前负载调整层级选择。本文受控模型的离散 LOD 可沿用既有简化流程，研究对象则限定为这些层级进入 3D Tiles 后的运行时选择，不把离线网格处理视为调度方法的创新来源。

多分辨率数据进入 Web 环境后，LOD 选择还受到设备能力、相机路径、内存占用和绘制负载的共同影响。Suarez 等围绕移动设备上的地形 LOD 实现开展性能研究，说明 iOS、Android 与浏览器环境中的硬件和运行条件会改变多分辨率绘制行为 [@Suarez2015]。Auer 等将语义分割的多分辨率三维模型用于文化遗产的 Web 可视化与查询，表明层次组织能够支持细节丰富模型的在线访问 [@Auer2014]。这些工作从移动性能和应用场景两侧说明了多分辨率传输的必要性，但其论证重点不在利用实时瓦片请求压力约束帧时分布尾部。3D Tiles 标准提供的几何误差与 SSE 则构成通用的层次细化接口 [@OGC3DTiles2022]；本文沿用该接口作为质量执行器，不提出新的瓦片格式、误差编码或内容组织方式。

## 2.2 预算约束下的运行时质量调节

自适应绘制关注的是在资源有限且负载变化的条件下，如何选择当下可承担的表示质量。Funkhouser 和 Sequin 的方法以用户给定的目标帧时约束显示选择，核心思想是将交互稳定性纳入质量优化，而不是始终追求最高精度 [@Funkhouser1993]。这一框架为本文采用明确帧时预算提供了理论起点，但其场景早于 Web 流式瓦片体系，并未包含网络请求与异步处理队列。若直接把经典帧时反馈移植到 3D Tiles，控制器仍可能在请求压力尚未转化为可见卡顿时缺少提前量。

运行时预测与反馈控制为提前或连续调节质量提供了两条路径。Yang 等通过简单控制机制连续调整帧缓冲 LOD 以维持目标帧率 [@Yang2008]；Zhang 等则通过在线预测与质量估计，在功耗预算下选择绘制配置，并在桌面和移动平台讨论其适用性 [@Zhang2018]。前者支撑本文设置离散 PI 控制基线，后者说明轻量预测可以服务于资源约束下的质量决策。二者的执行量分别是帧缓冲分辨率和功耗相关配置，而不是 Web 3D Tiles 的请求与处理状态。本文把受控量改为滚动 P95 帧时，并将公开请求反馈与交互阶段纳入决策条件；这种继承关系限定了本文的方法来源，也避免把一般性的反馈或预测式质量调节表述为新概念。

## 2.3 本文工作的定位

上述研究可以归纳为三条相互衔接但职责不同的技术路线：离线简化负责生成可替换的几何表示，多分辨率 Web 传输负责组织并按视点加载内容，运行时质量调节负责在动态资源边界下选择当前配置。本文位于第三条路线，并依赖前两条路线提供的数据层次与标准化执行接口。其具体问题不是证明更高精度的简化算法，也不是改变 3D Tiles 的层次结构，而是考察在现有 SSE 执行器之上，尾部帧时趋势、异步请求压力和交互状态能否共同形成稳定、可解释的调度信号。

因此，本文的创新边界应理解为一种受约束的调度组合及其验证设计：以 P95 帧时预算界定性能目标，以短时正趋势提供预警，以公开瓦片请求状态补充流式负载信息，再用交互非对称性、滞回和冷却条件限制质量振荡。现有文献矩阵能够支撑这些组成部分的来源、应用动机与差异边界，但不能据此扩大创新范围或预先断言该组合优于既有方法。方法是否降低预算超限、其视觉质量代价是否可接受、稳定控制是否减少反复切换，均须由既定的配对实验和消融分析回答。

# 3 方法

## 3.1 控制目标与遥测输入

本文将 Web 3D Tiles 的运行时细节调度表述为尾部帧时约束下的离散质量选择问题。设 30 FPS 对应的单帧预算为 $T=1000/30=33.333\ldots\ \mathrm{ms}$，控制目标是在当前设备与视点负载下，使最近窗口的 P95 帧时尽量不超过 $T$，同时从可行档位中选取尽可能小的最大屏幕空间误差（maximum screen-space error，SSE）。SSE 越小，Cesium 允许的投影误差越低，瓦片细化程度通常越高；SSE 增大则放宽细化条件，用视觉细节换取渲染和流式加载余量。控制器只改变 `Cesium3DTileset.maximumScreenSpaceError`，瓦片可见性判断、几何误差投影和层次细化仍由 Cesium 原有流程完成，因而本文方法属于已有 3D Tiles 选择管线之外的轻量调度层，而不是新的网格简化、瓦片编码或替代性细化算法。

浏览器通过 `requestAnimationFrame` 记录相邻回调的时间间隔。时刻 $t$ 的滑动窗口保留时间戳不早于 $t-2000\ \mathrm{ms}$ 的帧时样本，并按 500 ms 的控制间隔形成一次观测。将窗口内按升序排列的 $n$ 个有效帧时记为 $x_{(1)},\ldots,x_{(n)}$，实现以一基位置 $r=1+0.95(n-1)$ 在相邻次序统计量之间线性插值得到 $P_t$；该值就是控制器使用的窗口 P95 帧时。每次运行开始前先卸载上一轮瓦片集，并在空白场景下执行方法无关的帧时就绪检查：正式实验要求两个连续 2 s 窗口的 P95 均不高于 25 ms，最长等待 60 s。就绪通过后再加载目标瓦片集并进入 10 s 固定 SSE 16 预热；预热期间不更新自适应控制器或正式滚动 P95 窗口，测量开始时重置控制状态和帧时窗口，避免前一轮资源状态或初始化长帧污染正式阶段。

与帧时同步输入的流式加载信息来自 `Cesium3DTileset.loadProgress` 公共事件。若待请求瓦片数和处理中瓦片数分别为 $R_t$ 与 $C_t$，控制器使用的队列压力观测为

$$
Q_t=\max(0,R_t)+\max(0,C_t).
$$

`tileLoad`、`tileVisible` 与 `tileFailed` 公共事件分别累计已加载瓦片、当前控制区间内可见瓦片的几何误差以及加载失败信息。这些量用于有效性检查和质量诊断，不直接进入 SSE 决策。每次控制更新还接收布尔交互标记 $I_t$：确定性实验由场景驱动器给出该标记，实际交互使用时可由浏览器输入事件提供。由此，一次更新的决策输入由 $P_t$、$R_t$、$C_t$、$I_t$ 和当前时间戳组成，不依赖 Cesium 私有统计字段。

## 3.2 尾部帧时平滑与短期预测

直接依据单个 P95 窗口调节 SSE 容易受偶发长帧影响。控制器对 $P_t$ 进行指数平滑，首个有效观测以 $L_0=P_0$ 初始化，后续更新为

$$
L_t=0.4P_t+0.6L_{t-1}.
$$

控制器保存最近四个平滑估计及其以秒为单位的实际时间戳。对样本 $(\tau_i,L_i)$，$i=1,\ldots,m$，其中 $m\leq4$，趋势斜率按最小二乘法计算为

$$
b_t=\frac{\sum_{i=1}^{m}(\tau_i-\bar{\tau})(L_i-\bar{L})}
{\sum_{i=1}^{m}(\tau_i-\bar{\tau})^2}.
$$

当有效历史少于两个点或时间方差为零时，$b_t$ 取 0。冻结的预测时域为 $H=1\ \mathrm{s}$，下一秒的尾部帧时预测写为

$$
F_{t+H}=\max\left(P_t,\ L_t+\max(0,b_t)H\right).
$$

斜率的单位为毫秒每秒，因此乘以 $H$ 后可直接与 $L_t$ 相加。预测仅外推上升趋势；负斜率被截断为 0，使短时下降不会压低预测值并提前触发质量恢复。预测值同时以当前观测 $P_t$ 为下界，避免 EWMA 在突发上升阶段使所谓“下一秒预测”反而低于已经观测到的尾部帧时。控制判断使用 $W_t=\max(P_t,F_{t+H})$，当前超限与预测超限因而进入同一条降质路径，而恢复路径仍要求当前值和预测值分别满足余量条件。

## 3.3 请求压力与交互门控

请求队列采用带释放条件的锁存状态，而不是把任意非零队列都视为高压。若 $Q_t$ 相对上一控制更新连续上升两次，队列从首次非零起持续达到 1500 ms，或单个控制区间出现 $Q_t \geq 24$ 的大请求脉冲，请求压力状态置为高。队列下降但尚未清空时不立即释放该状态；只有 $Q_t=0$ 连续保持 1000 ms，压力状态才复位。该规则把小的短暂请求事件与持续细化压力或大幅请求脉冲区分开，并避免队列在零附近波动时频繁改变门控结果。

交互状态采用非对称处理。尾部帧时超限和“预测尾部升高且请求压力为高”的判断位于交互门控之前，因此相机交互期间仍允许紧急降低质量。若前述降质条件均未触发，只要 $I_t$ 为真，控制器便阻止质量升级并清零恢复计数。控制器记录最近一次交互时间；交互结束后还需等待 1500 ms，恢复条件才可能成立。这一保持区间使相机停止后的残余请求和瓦片处理有时间消退，避免刚结束操作就提高细节而重新推高负载。

## 3.4 离散 SSE 决策与稳定性约束

SSE 只能取冻结档位

$$
\mathcal{S}=\{4,6,8,12,16,24,32,48,64\},
$$

初始档位为 16。设 $k_t$ 为当前 SSE 在升序数组 $\mathcal{S}$ 中的索引。质量降低是增大索引，质量恢复是减小索引；索引始终截断在 $[0,8]$ 内。预热结束后，控制器按固定优先级处理每次观测。若 $W_t>T$ 且距上次动作不少于 500 ms，则触发尾部超限降质；当 $W_t>1.2T=40\ \mathrm{ms}$ 时令 $k_{t+1}=\min(k_t+2,8)$，否则令 $k_{t+1}=\min(k_t+1,8)$。这里采用严格大于关系，等于预算或临界阈值本身不触发对应分支。

若尾部超限分支未触发，但请求压力为高且 $F_{t+H}>0.9T=30\ \mathrm{ms}$，控制器在满足同一 500 ms 降质冷却条件时预先增加一个 SSE 档位。该分支要求预测值与请求压力同时成立，避免仅因队列存在便降低细节。完成两类降质动作后，恢复计数归零，控制状态记为 `PRESSURE`。若处于交互期，控制器随后返回保持动作；因此交互只阻断升级，不覆盖已满足条件的降质决策。

质量恢复需要同时满足 $P_t<0.8T$、$F_{t+H}<0.8T$、请求压力为低以及距最近交互不少于 1500 ms，其中 $0.8T=26.667\ldots\ \mathrm{ms}$。每个符合条件的 500 ms 更新使恢复计数增加 1，任一条件失效即将计数清零。连续四次更新均合格且距上次 SSE 动作不少于 1500 ms 时，控制器执行 $k_{t+1}=\max(k_t-1,0)$，每次只恢复一个质量档位。四个更新对应约 2 s 的持续余量，配合 1.5 s 升级冷却、0.5 s 降质冷却以及 80%--90%--100% 的分层阈值，构成对恢复更谨慎、对超限更迅速的非对称迟滞。未满足任何动作条件时保持当前 SSE，并依据上下文输出 `WARMUP`、`STABLE`、`PRESSURE`、`INTERACTING` 或 `RECOVERY` 状态。

## 3.5 决策输出与实验对应

每次更新输出控制状态、动作类型、动作原因、当前 SSE、平滑 P95、预测 P95、请求队列及压力标记。基准程序在非预热阶段把输出 SSE 写回 `tileset.maximumScreenSpaceError`，并将同一控制区间的帧时、队列、可见几何误差和动作记录到结果行。该数据流使输入观测、状态判定和执行结果能够按时间对应，也使超限窗口比例、时间加权 SSE、请求队列峰值与面积、切换次数、反转次数和恢复时延可从运行记录复算。

方法中的四类信息分别对应后续消融条件：关闭预测时以当前 $P_t$ 代替 $F_{t+H}$，关闭请求反馈时不启用压力门控，关闭交互感知时不使用交互升级保持，关闭稳定性控制时移除动作冷却并将恢复所需连续更新数降为 1。主方法不进行离线或在线模型训练，也不按设备拟合参数；全部阈值、窗口、档位、预测定义、请求脉冲阈值、运行前就绪规则以及“测量阶段首个控制决策必须等待完整 2 s 帧时窗口”的执行规则由 `2.3.6` 协议记录。`2.3.6` 新增 S3 `pressureBurst` 压力工作负载，并已在 PC-A gate 通过后冻结用于 Android-A pilot；它不改变控制器阈值或统计方案，也不构成确认性实验结果。因而实验所检验的是短期尾部预测、公开流式请求反馈、交互门控和稳定性约束组合后对运行时调度的作用，而不是设备专用学习器或新的 LOD 表示带来的收益。

# 4 实验设计

## 4.1 研究问题与设计原则

本节给出动态层次细节调度方法的预注册实验方案，所回答的问题是：在桌面端与 Android Web 客户端上，一个联合短期尾帧预测、公开 3D Tiles 请求反馈、交互状态和稳定性约束的轻量控制器，能否在维持视觉质量的同时降低 P95 帧时预算违规。帧时预算设为 30 FPS 对应的 $T=1000/30=33.333\ldots\ \mathrm{ms}$。控制器每 500 ms 更新一次，统计窗口长度为 2 s，预测时域为 1 s。实验的主要约束变量是窗口 P95 帧时是否超过 $T$，但统计推断单位是一次完整浏览器运行，而不是单帧或相互重叠的控制窗口，以避免把同一运行中的时间相关观测误当作独立样本。

正式采集开始后，帧窗口、控制周期、预测时域、SSE 档位及阈值均保持冻结。控制器采用 $\{4,6,8,12,16,24,32,48,64\}$ 的离散 SSE 阶梯，初值为 16；其余预测、请求压力、交互保持和冷却参数均按冻结协议执行。任何参数修改都形成新的协议版本，并重新运行所有受影响条件。实验只评价标准 Cesium SSE 执行器之上的客户端调度策略，不把研究范围扩展为网格简化算法或 3D Tiles 编码方法比较。

## 4.3 数据集与场景

数据按研究用途严格分层。C0 为项目附带的 Stanford Dragon 离散 LOD 样例，仅用于规范视角和质量标定；C1 为基于公开样例构造的四层、85 瓦片合成压力集，仅用于诊断请求行为和标定 PI 参数，二者均不进入确认性统计。正式推断使用官方 3DBAG `v20250903` Cesium 3D Tiles 仓库的两个冻结子集 [@Peters2022; @ThreeDBAGCopyright2025]：D1 为 Amsterdam 中心区，包含 307 个内容瓦片、约 193.6 MB；D2 为相互独立的 Rotterdam 空间子集，包含 244 个内容瓦片、约 180.4 MB。两者均按 CC BY 4.0 使用，每个本地文件的路径、字节数和 SHA-256 均写入 `provenance.json`，清单文件自身的哈希也冻结在实验配置中。

正式 D1 与 D2 实验统一使用局域网原始响应，不施加人工时延。40 ms 与 80 ms 响应延迟只允许用于 C1 诊断，服务器会拒绝把延迟配置用于正式数据集，因而不得将诊断结果解释为特定公共网络或移动网络性能。Taipei 101 与大雁塔现有副本的论文发表许可均未解决，仅可作为本地演示，不能进入统计、插图或泛化论证。

两类相机场景用于区分平稳浏览和交互恢复行为。每次场景开始前先通过空白场景帧时就绪门槛，随后加载目标瓦片集并预热 10 s。S1 在预热后进行 40 s 匀速环绕。S2 同样先预热 10 s，随后执行四个“交互—恢复”周期；每个周期先用 6 s 跨方位单调接近目标，相机距离由数据集包围球半径的 3.6 倍降至 0.9 倍，再在该近景视点静止保持 4 s，使已选择的细化请求能够持续并完成。当前 `2.3.6` 协议另增 S3 `pressureBurst`：每周期用 4 s 接近至 0.7 倍包围球半径附近，并将近景静止保持延长为 6 s；该场景已冻结用于 Android-A pilot，但在确认性矩阵单独释放前不得作为确认性实验结果。场景驱动器提供确定性的相机路径、阶段编号及交互标记，正式运行清单同时保存预定时长和实际时长；仅烟雾测试允许二者不同，烟雾测试数据不进入正式推断。

## 4.4 对照方法、消融与运行矩阵

主比较包含六种方法：固定 SSE 8、固定 SSE 16、初始 SSE 为 16 的 Cesium 动态 SSE、反应式 P95 控制器、离散 PI 控制器以及本文控制器。PI 参数仅在 C1/S2 的预设 $4\times4$ 网格上标定一次，每对参数重复 4 次，并按“违规率优先、0.01 绝对违规率带内再比较时间加权 SSE 与切换次数”的规则选择；所选参数须在确认性实验前冻结。所有方法共享相同资源、绘图缓冲区、相机轨迹、预热和测量时长，不允许针对单一方法调整数据或场景。

消融实验限定在主要确认条件 D1/S2，分别移除预测项、请求压力项、交互感知项和稳定性约束，其余参数保持与完整方法一致。该设计使四项方法贡献分别对应一组可检验对照，且不会把多个组件同时删除后产生的复合变化归因于某个单独模块。

方法顺序在每个“数据集—场景—重复”配对块内依据运行清单中的随机种子打乱。D1/S1、D2/S1 和 D2/S2 各执行 8 个六方法配对块，主要条件 D1/S2 执行 12 个配对块，因此每台物理设备的主矩阵为 $(8+12+8+8)\times6=216$ 次计划运行。D1/S2 的四个消融版本各重复 8 次，新增 32 次；无效尝试保留审计记录并自动补跑至多两次。PI 网格标定另含 64 次试验，只在指定调参 PC 上执行且不与确认性数据合并。

## 4.5 评价指标与数据记录

主要终点为一次有效运行中，P95 帧时超过 $33.333\ldots\ \mathrm{ms}$ 的有效 2 s 控制窗口占比。每次运行先形成该违规率摘要，再以运行级摘要进入配对统计分析。原始帧 P95/P99、单帧预算违规率、请求队列峰值及队列曲线下面积、传输字节数、时间加权平均 SSE、可见瓦片几何误差、切换频率、反转次数和恢复时间作为次要指标。其中时间加权 SSE 越低只表示控制器选择了更细的显示档位，不单独等同于更高的感知质量；请求量与字节数也只作为资源行为指标解释。

视觉质量在六个固定规范视角下，以 SSE 4 渲染作为参考，计算窗口化结构相似性指标 SSIM，并结合可见瓦片平均与最大几何误差进行报告。相对于反应式控制器，SSIM 的预设非劣界值为 0.02。冻结 PyTorch 与模型版本后可补充 LPIPS，但 LPIPS 不替代预声明的 SSIM 非劣判断。预测模块另报告一秒期 MAE、当前 P95 持续值基线 MAE、超限预测的精确率/召回率/F1 与平均预警提前量。

每次运行保存 RunManifest、逐控制周期 TelemetryRow 和 RunSummary。运行清单至少包含运行标识、方法、数据集、场景、重复编号、随机种子、缓冲区尺寸、预热与测量时长、帧时预算及浏览器设备元数据。逐周期记录当前与预测 P95、请求队列、压力状态、SSE、控制器状态、动作原因、可见瓦片事件和几何误差，并逐窗核验绘图缓冲区。运行摘要记录有效窗口数、违规率、原始帧分位数、资源计数、传输量及稳定性指标。JavaScript 非有限值统一写为 JSON `null`，CSV 对应单元格留空；缺失值不得静默替换为 0。

## 4.6 有效性规则与统计分析

若运行前空白场景帧时就绪检查超时、页面进入隐藏状态、窗口失去焦点、绘图缓冲区不是 $960\times540$、未记录到有效控制窗口、Resource Timing 数据缺失或发生瓦片加载失败，则该次运行判为无效并按原条件自动补跑至多两次。除这些预先声明的规则外，不依据观测到的指标高低事后删除运行。分析前先核对每个配对块的六种主方法是否完整；不完整块不进入完整配对检验，并须在数据清单中保留失效原因和补跑记录。

六种主方法先在每个“物理设备—数据集—场景”分层内基于完整配对块进行 Friedman 检验。计划比较为本文方法分别对离散 PI、反应式 P95 与 Cesium 动态 SSE，采用双侧配对 Wilcoxon 符号秩检验，并对全部预设比较用 Holm 方法控制族错误率。除调整后的 $p$ 值外，还报告 Hodges–Lehmann 配对差异估计、配对秩二列效应量及 Bootstrap 95% 置信区间。Bootstrap 以运行级完整配对块为重采样单位，固定执行 10,000 次重采样，分析随机种子为 `20260823`。不以跨设备混合的单一 $p$ 值替代各物理设备分层证据。

预设发表判定仅用于约束结果解释，不构成本节的实验结果：在 D1/S2 上，本文方法相对反应式方法的违规率中位相对变化须在每台物理设备上均达到至少 20% 的降低方向，预设分层比较的 Holm 校正后 $p<0.05$，SSIM 满足 0.02 的非劣界限，切换频率不高于反应式方法，预测 MAE 低于持续值基线，并且 D2 上效应方向一致。任何未达到的条件均按实际数据报告，不调整阈值或选择性省略。

# 5 实验结果

本节围绕尾帧预算约束、视觉质量代价、控制稳定性、组件作用和独立空间数据验证五个方面组织证据。当前正式实验矩阵尚未完成，C1—C5 与 C7 均处于 `UNMEASURED` 状态，因此以下内容仅规定结果回填后的比较关系、统计量和解释边界，不构成任何性能、质量或泛化结论。各项判断须以两台 PC 与物理 Android 上完成的方法内随机顺序配对实验为依据；缺失运行、无效运行和不完整的六方法配对块不得用于支持主张。

## 5.1 尾帧预算约束

[待正式实验回填] 正式矩阵完成后，本小节将按物理设备、数据集和场景报告 fixed SSE 8、fixed SSE 16、Cesium dynamic SSE、reactive、PI 与 proposed 六种方法的 P95 控制窗口超出 33.333 ms 预算的比例。描述性统计须交代完整六方法配对块数量；每个分层的 Friedman 检验，以及 proposed 分别对 PI、reactive 和 Cesium dynamic 的 Wilcoxon-Holm 比较，均须回填统计量、校正 p 值、Hodges—Lehmann 差值、配对秩二列效应量和 95% Bootstrap 置信区间。只有效应方向、区间估计和多重比较校正结果共同支持时，才能更新 C1。

## 5.2 质量—性能权衡

[待正式实验回填] 本小节将把尾帧预算表现与时间加权 SSE、六个规范视角的窗口 SSIM、补充 LPIPS 以及可见瓦片几何误差对应起来。SSIM 计算以 SSE 4 渲染为同视角参考，视觉质量判断采用预先声明的 0.02 非劣界值；LPIPS 仅作补充，不可在 SSIM 未满足预设判据时替代非劣证据。C2 只有在尾帧约束证据与视觉质量证据均完整时才可更新。

## 5.3 控制稳定性与恢复

[待正式实验回填] 控制稳定性将针对 reactive 与 proposed 回填每分钟 SSE 切换次数、相邻反向切换次数和交互结束后的恢复时延，并按设备、数据集、场景及重复编号保持配对。结果叙述应同时给出分布统计和配对差，区分减少无效振荡与延迟质量恢复这两种可能并存的现象。若 proposed 的切换或反转较少，但恢复时延越过预设容忍范围，结论应保留该权衡；若不同设备上的方向不一致，则分别报告而不合并为稳定性优势。C3 还须与无稳定性保护消融的结果相互印证，缺少该消融时只能呈现测量值，不能把观察到的切换差异归因于滞回、冷却时间或连续资格判定。

# 6 讨论

## 6.1 方法定位与创新边界

本文工作的核心是围绕既有 3D Tiles 层次细节选择机制增加一个客户端运行时调度层。控制器以 Cesium 的 `maximumScreenSpaceError` 为执行量，综合滚动窗口 P95 帧时、短时上升趋势、公开瓦片请求状态和交互状态，在离散 SSE 档位之间进行调整。Cesium 仍负责几何误差投影、可见性判断和瓦片细化，模型的离散层次也仍由离线处理阶段生成。因此，本文的创新不在于提出新的网格简化算法、几何误差定义、3D Tiles 编码格式或引擎内部细化规则，而在于把尾部帧时约束、流式请求压力和交互阶段差异组织为一个轻量、可解释且可复现的调度策略。

这一定位也限定了本文能够回答的问题。研究关注的是：在既定数据层次、渲染引擎和 SSE 执行接口下，预测性控制能否比固定阈值、Cesium 动态 SSE、离散 PI 及仅依赖当前 P95 的反应式控制更好地处理帧时预算与视觉细节之间的关系。即使后续实验观察到性能改善，也只能说明这些运行时信号及其组合决策对当前测试条件下的调度有效，不能据此推断基础 LOD 表示本身得到改进。

现阶段主张登记表仅支持实现层面的判断：控制器通过 Cesium 公开事件获取请求和瓦片状态，不依赖私有统计接口，并已有相应单元测试与浏览器冒烟验证。该证据可以支持“方法已经定义并实现”以及“实现路径可复核”，但不能支持违反率降低、视觉质量非劣、振荡减少或冷缓存交互阶段受益等效果性结论。工程可运行性解决的是系统是否按预定逻辑执行，正式对照实验解决的才是该逻辑是否产生预声明效应，两类证据在本文中必须保持分离。

## 6.2 结果解释与主张边界

[待正式实验回填：C1。仅在全部物理设备的 D1/S2 六方法配对区组完整、分层 Wilcoxon 检验经 Holm 校正，并同时报告效应量与置信区间后，讨论所提方法相对于 PI 与反应式控制器的 P95 窗口超预算率差异。若统计证据不足或不同设备方向不一致，应如实报告。]

[待正式实验回填：C2。结合六个标准视角的 SSIM、时间加权 SSE 和可见几何误差，依据预声明的 0.02 非劣界值判断性能变化是否以不可接受的视觉质量损失为代价。只有非劣判定成立时，才可讨论质量—性能折中；单独的平均 SSIM 或局部视角结果不能替代该判定。]

[待正式实验回填：C3、C4 与 C7。使用每分钟切换次数、反转次数、恢复时延及无稳定机制消融解释稳定性控制；使用全部设备上的 D1/S2 无请求反馈消融判断请求信号增量价值；以预测 MAE 相对持续值基线及无预测消融判断预测器是否真正提供提前信息。]

上述回填应同时呈现不利结果与代价。例如，超预算率下降若伴随 SSE 长时间停留在较粗档位，说明控制策略可能以持续降低细节换取帧时余量；切换次数减少若伴随恢复延迟增加，则反映稳定机制在抑制振荡与恢复速度之间存在权衡。讨论的任务不是重复结果表，而是把效应方向、统计不确定性、视觉代价和机制解释对应起来。D2 只能支持同一 3DBAG 数据生产流程内的空间区域迁移；未授权的文化遗产和建筑模型不进入泛化论证。

## 6.3 研究局限

### 6.3.1 设备覆盖与外推范围

本研究预定在两台桌面 PC 和一部 Android 手机上进行验证。三个物理设备能够检验部分平台与性能档位差异，但样本规模仍不足以代表浏览器生态中的硬件异质性。GPU 架构、CPU 调度、内存、刷新率、热降频和浏览器版本均可能改变帧时分布及请求处理节奏；即便三台设备方向一致，也只能形成有限的跨设备验证。

### 6.3.2 帧时测量口径

本文通过 `requestAnimationFrame` 采集浏览器呈现节奏，由此计算滚动窗口 P95。该指标贴近用户实际感知到的页面更新间隔，适合作为客户端调度器的在线输入，却不是隔离的 GPU 渲染耗时。主线程脚本、资源解码、垃圾回收、浏览器合成、操作系统调度和 GPU 同步都可能反映在测量值中。研究结果因此应解释为对浏览器端综合帧时压力的调节，而不能归结为对 GPU 性能的直接优化。若要辨析各类开销的因果贡献，还需要结合更细粒度的 CPU/GPU 时间戳和性能跟踪工具。

### 6.3.3 视觉质量代理的适用范围

六个标准视角下相对于 SSE 4 参考图像的窗口化 SSIM，为不同调度策略提供可重复的屏幕空间质量比较，但只覆盖预选视角与对应成像条件。补充 LPIPS 可增加感知特征距离证据，仍不能完整表示三维几何偏差、纹理语义或连续运动中的瞬时细节损失。二者须与时间加权 SSE、可见瓦片几何误差及代表性画面共同解释，不能替代几何误差分析。

### 6.3.4 数据来源与外推范围

四层、85 瓦片合成集只承担诊断和调参，不进入确认性推断。D1 与 D2 是具备可核验许可和哈希清单的真实城市数据，但二者共享 3DBAG 数据生产流程，因此 D2 只能检验空间区域迁移。对摄影测量、工程或文化遗产数据的外推仍需独立且获授权的数据源；当前 Taipei 101 与大雁塔副本不能提供这类证据。

## 6.4 后续工作

后续验证应围绕现有证据缺口展开，而不是扩大当前结论。设备层面可增加不同 GPU 档位、刷新率和移动端热状态，并记录浏览器版本与系统功耗策略；网络层面可设置带宽、时延、抖动和缓存状态的组合，以区分渲染压力与流式请求压力。方法层面可比较不同预测窗口、阈值和冷却参数，检验固定参数对场景变化的敏感性；只有在轻量基线得到充分验证后，才有必要引入学习型预测器，并以额外训练成本、解释性和跨设备迁移能力作为共同评价条件。真实案例扩展必须以可追溯来源和明确授权为前提，同时保留与公开基准一致的配对协议，使新增证据能够与现有结果比较。

# 7 结论

本文定义并实现了一种面向 Web 3D Tiles 的可解释尾部帧时约束调度方法。该方法不改变 3D Tiles 的几何表示和 Cesium 的细化流程，而是通过标准 SSE 执行接口，把滚动 P95 的短时预测、公开请求反馈、交互感知的非对称决策和稳定性约束结合起来。相应实验方案采用固定绘制分辨率、确定性相机路径、成组随机顺序、跨设备配对重复、组件消融和预声明统计分析，以区分实现可行性、整体效果与各组成机制的贡献。

[待正式实验回填：仅在 C1—C5 与 C7 的证据状态完成复核后，用一句话概括 P95 窗口超预算率、SSIM 非劣性、预测增量、控制稳定性和 D2 迁移方向；应同时保留统计不确定性及观察到的代价，不得依据实现测试或工程冒烟数据填写。]

在正式结果完成前，本文能够得出的结论限于方法已被明确描述、其公开接口实现可复核、两个真实数据集已冻结且评价路径已经预先规定，尚不能断言该方法降低了尾部帧时违规、保持了视觉质量或减少了控制振荡。三台物理设备、浏览器综合帧时测量、规范视角感知指标以及同源 3DBAG 子集共同限定未来结论的外推范围。扩大设备与独立数据源、补充细粒度性能测量并覆盖连续视点质量，是后续研究可沿用的方向。
